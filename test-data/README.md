# 测试数据

## 文件说明

| 文件 | 用途 |
|---|---|
| `学生名单-测试用.xlsx` | **导入功能的测试文件**，含正常数据与故意构造的错误行 |
| `学生名单-测试用-预期结果.md` | 该文件的**预期导入结果**，由脚本依据真实导入代码自动生成，可用于逐条比对 |

## 怎么用

1. 小程序 → 管理员登录 → 学生名单 → 右上角「⇪」→ 选择 `学生名单-测试用.xlsx`
2. 导入完成后会弹出结果，对照 `学生名单-测试用-预期结果.md` 核对

## 这个文件刻意设计成"不好解析"

它同时覆盖了导入功能容易出问题的几个点：

| 设计 | 验证什么 |
|---|---|
| 前两行是说明文字，第 3 行才是表头 | 表头**不在首行**时能否正确探测 |
| 表头顺序为：序号、姓名、备注、学号、班级、辅导员 | 能否按**列名**而非固定列位置识别 |
| 含"序号""备注""辅导员"等无关列 | 多余列是否被正确忽略 |
| 中间有两个空行 | 空行是否被跳过、不计入总数 |
| 两条记录的学号是**数字类型**（`20230202001`） | 数字型学号会不会被转成 `2.02302E+10` 这类科学计数法 |
| 第 17 行的学号与第 4 行重复 | **文件内**学号查重是否生效 |
| 三条记录分别缺班级 / 姓名 / 学号 | 必填校验是否生效、失败原因是否准确 |
| 第二个工作表故意用不同表头 | 是否**只读第一个**工作表 |

## 预期结果摘要

- 共读取 **16** 行（空行不计入）
- 成功导入 **12** 条
- 失败 **4** 条：班级为空、姓名为空、学号为空、文件内学号重复（各 1 条）

## 重复导入测试

**对同一个文件再导入一次**，预期：

- 成功 **0** 条
- 失败 **16** 条，原因全部是「该学号已存在于名单中」

这验证 `users` 集合的 `sno` 唯一索引生效，重复导入不会产生重复学生。

## 重新生成

如果修改了 `cloudfunctions/student/index.js` 的导入逻辑，请重新生成预期结果：

```bash
node scripts/make-test-roster.js     # 重新生成 xlsx
node scripts/verify-test-roster.js   # 依据真实导入代码重算预期结果
```

> `verify-test-roster.js` 直接从 `cloudfunctions/student/index.js` 中抽取表头识别与单元格读取函数来跑，
> 因此 `预期结果.md` 反映的是**代码的真实行为**，不是人工推测。改代码后务必重跑。
