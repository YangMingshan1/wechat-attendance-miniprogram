# 云函数公共代码

本目录存放 7 个云函数共用的模块。**它本身不是一个云函数**（名字以下划线开头，微信开发者工具不会把它当作云函数上传）。

## 为什么是"复制"而不是"引用"

微信云开发的每个云函数都是**独立打包、独立部署**的，云函数目录之间无法互相 `require`。常见的三种处理方式：

| 方案 | 做法 | 取舍 |
|---|---|---|
| **A（本项目采用）** | 把公共代码**复制**进每个云函数目录 | 免构建、可直接右键上传部署；代价是改公共代码后需同步 |
| B | 把公共代码发布成私有 npm 包 | 需要 npm 私服或每次改版本号，课程项目过重 |
| C | 云函数目录使用软链接 / 构建脚本打包 | 依赖本地构建步骤，换台电脑就失效 |

课程项目优先保证"老师拿到代码能直接跑起来"，因此选择方案 A，并提供一个同步脚本降低维护成本。

## 公共模块清单

| 文件 | 职责 |
|---|---|
| `response.js` | 统一返回体 `{code,msg,data}`、错误码表、`withHandler` 异常包装器 |
| `auth.js` | 管理员鉴权（openid 白名单 + `admins` 集合）、学生身份校验（学号+姓名） |
| `distance.js` | Haversine 距离计算、经纬度合法性校验 |
| `utils.js` | 类型转换、北京时间格式化、批次号、唯一键冲突识别、分页归一化 |

## 如何同步到各云函数

在项目根目录执行：

```bash
node scripts/sync-common.js
```

脚本会把本目录下的 `.js` 文件复制到每一个云函数目录的 `common/` 子目录中。云函数内这样引用：

```js
const { ok, fail, CODE, withHandler } = require('./common/response');
const { requireAdmin } = require('./common/auth');
const { haversine } = require('./common/distance');
```

**修改公共代码后请务必重新执行同步脚本，并在开发者工具中重新上传受影响的云函数**，否则线上仍是旧代码。
