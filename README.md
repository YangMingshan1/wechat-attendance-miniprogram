# 微信小程序定位签到系统

基于**微信小程序 + 微信云开发**的课堂定位签到系统。管理员与学生**共用一套小程序**，首页选择身份进入。

- **管理员**：微信授权登录 · 课程管理（单点位 + 距离阈值）· Excel 批量导入学生名单 · 签到记录查看／修改／删除 · 导出签到 Excel
- **学生**：学号 + 姓名登录（无密码、不绑定微信）· 微信原生定位签到 · 超出阈值禁止签到

## 功能一览

### 管理员端

| 功能 | 说明 |
|---|---|
| 微信授权登录 | openid 白名单校验，非管理员账号无法进入 |
| 课程管理 | 新增／编辑／停用／删除课程；每门课程**仅 1 个签到点位** |
| 点位设置 | 通过微信地图选点（`wx.chooseLocation`）确定经纬度，避免手工填错 |
| 距离阈值 | 可自定义，**默认 50 米** |
| 学生名单 | Excel 批量导入（班级、姓名、学号）；支持搜索、分页、删除 |
| 签到记录 | 查看全部记录，按课程／班级筛选，支持修改与删除 |
| 导出 | 导出签到记录为 Excel 文件，支持转发与保存 |

### 学生端

| 功能 | 说明 |
|---|---|
| 登录 | 学号 + 姓名与后台名单匹配即可登录；**无密码、不绑定 openid** |
| 课程列表 | 仅展示管理员**启用**的课程 |
| 定位签到 | 调用微信原生定位 API，经纬度上报云端裁决 |
| 超范围拦截 | 超出阈值禁止签到，并提示实际距离与允许范围 |
| 重复签到拦截 | 同一课程同一设备只能签到 1 次，**无例外** |

## 技术栈与架构

| 层 | 技术 |
|---|---|
| 前端 | 微信小程序原生开发（WXML / WXSS / JS），无第三方 UI 库 |
| 后端 | 微信云开发云函数（Node.js） |
| 数据库 | 微信云开发数据库（文档型 NoSQL） |
| 文件 | 云存储（Excel 导入导出中转） |
| 依赖 | `wx-server-sdk`、`xlsx`(SheetJS) |

### 架构要点

```
小程序端                        云端
┌──────────────┐              ┌─────────────────────────────┐
│ 页面 (12 个)  │              │  云函数 (7 个)               │
│              │  callFunction │                             │
│  utils/api   │ ───────────► │  login  course  student     │
│              │              │  record signIn  export  init│
│  ✗ 不直连数据库│ ◄─────────── │         │                   │
└──────────────┘   {code,msg,  │         ▼                   │
                      data}   │  云开发数据库 (5 个集合)      │
                              │  courses users records      │
                              │  admins  devices            │
                              └─────────────────────────────┘
```

**关键设计：小程序端不直连数据库，所有数据操作都通过云函数完成。**

原因是云开发默认权限模型（"仅创建者可读写"）无法表达本系统的需求：管理员需要跨用户读取全部签到记录，而学生**不绑定 openid**。因此所有集合的权限都设为"仅管理端可读写"，客户端无法直接访问数据，签到规则也就无法从客户端绕过。

## 快速开始（部署步骤）

### 前置条件

- 微信开发者工具（稳定版）
- 一个已注册的小程序 AppID（**测试号不支持云开发**）
- 小程序后台已开通云开发

### 步骤 1 · 导入项目

1. 打开微信开发者工具 → 导入项目
2. 目录选择本项目根目录
3. **AppID 填写你自己的小程序 AppID**（`project.config.json` 中默认为 `touristappid`，需替换）

### 步骤 2 · 开通并配置云环境

1. 点击工具栏「云开发」→ 开通（选择免费额度即可）
2. 记下**环境 ID**
3. 若你有多个云环境，修改 `miniprogram/app.js`：

   ```js
   wx.cloud.init({
     env: '你的环境ID',      // 替换 wx.cloud.DYNAMIC_CURRENT_ENV
     traceUser: true
   })
   ```

   只有一个环境时保持 `wx.cloud.DYNAMIC_CURRENT_ENV` 即可。

### 步骤 3 · 部署云函数

在 `cloudfunctions` 目录下，对**每一个云函数目录**右键 → **上传并部署：云端安装依赖**：

```
init  login  course  student  record  signIn  export
```

> 顺序不强制，但 `init` 建议先部署，因为后续步骤要用它初始化数据库。
>
> `student` 与 `export` 依赖 `xlsx`，**必须**选择「云端安装依赖」，否则会报 `Cannot find module 'xlsx'`。

### 步骤 4 · 配置管理员白名单

1. 修改云函数环境变量：开发者工具 → 云开发控制台 → 云函数 → `login` → 配置 → 环境变量，新增：

   | 变量名 | 值 |
   |---|---|
   | `ADMIN_OPENIDS` | 你的微信 openid（多个用英文逗号分隔） |

2. 不知道自己 openid 时：
   - 在小程序首页点「管理员登录」→「部署者：查看本机 openid」，会弹出当前 openid；
   - 或在开发者工具中调用 `login` 云函数的 `whoami` 动作。

3. 建议同时给 `init` 云函数配置同样的 `ADMIN_OPENIDS`（`init` 会把白名单写入 `admins` 集合）。

### 步骤 5 · 初始化数据库

在开发者工具中右键 `init` 云函数 → **云端测试**，事件参数填：

```json
{ "action": "setup" }
```

返回结果会列出：

- `collections`：5 个集合的创建情况
- `indexes`：7 个索引的创建情况
- `needManualIndexes`：**若大于 0，需要按提示在控制台手工建索引**

> ⚠️ **务必确认 `records` 集合的复合唯一索引 `uk_course_device`（`courseId` + `deviceId`，唯一）已建立成功。**
> 它是"同一课程同一设备只能签到 1 次"这一业务约束的实现载体。缺少该索引时功能表面正常，但在并发请求下会写入重复记录，规则被破坏。

手工建索引路径：云开发控制台 → 数据库 → 选择集合 → 索引管理 → 新建索引。完整索引清单见 [`docs/database-design.md`](docs/database-design.md#7-索引清单--部署必做)。

### 步骤 6 · 设置数据库权限（重要）

云开发控制台 → 数据库 → **对全部 5 个集合逐一**设置权限为「**所有用户不可读写**」（自定义安全规则）：

```json
{ "read": false, "write": false }
```

**验证方式**：在小程序端执行 `wx.cloud.database().collection('records').get()`，应返回权限错误。若返回数据，说明配置不正确。

### 步骤 7 · 配置隐私与接口权限

1. **接口权限**：小程序管理后台 → 开发管理 → 接口设置 → 申请开通
   - `wx.getLocation`（获取当前地理位置）
   - `wx.chooseLocation`（打开地图选择位置）

   本项目已在 `miniprogram/app.json` 中声明 `requiredPrivateInfos` 与 `permission.scope.userLocation`。

2. **隐私协议**：小程序管理后台 → 设置 → 服务内容声明 → 用户隐私保护指引，声明收集"位置信息"，用途填写"用于判断学生是否在签到点位允许范围内"。

> 自 2023 年起，未声明隐私协议会导致 `wx.getLocation` 直接调用失败。

### 步骤 8 · 运行

编译运行小程序：

1. 首页选择「管理员登录」→ 授权 → 进入工作台
2. 「课程管理」→ 新增课程 → 点击地图选择签到点位 → 设置阈值 → 保存
3. 「学生名单」→ 点击「Excel 批量导入」

   Excel 模板（第一行必须是表头，列的**顺序不限**，也允许有额外的"序号""备注"列）：

   | 班级 | 姓名 | 学号 |
   |---|---|---|
   | 软件工程 2301 班 | 李小明 | 20230101001 |
   | 软件工程 2301 班 | 王小红 | 20230101002 |

4. 切回首页 →「学生登录」→ 输入名单中的学号与姓名 → 选择课程 → 签到

## 数据库设计

5 个集合：`courses`、`users`、`records`、`admins`、`devices`。

| 集合 | 作用 | 关键约束 |
|---|---|---|
| `courses` | 课程与签到点位 | `latitude`/`longitude` 为**标量**（结构上无法表达多点位）；`radius` 默认 50 |
| `users` | 学生名单 | `sno` 唯一索引；**无 password、无 openid 字段** |
| `records` | 签到记录 | **复合唯一索引 `courseId + deviceId`**；**无 status 字段**（无迟到/缺勤） |
| `admins` | 管理员白名单 | `openid` 唯一索引 |
| `devices` | 设备审计（可选） | 不参与任何业务判定 |

字段级的完整定义、示例值、索引清单见 **[docs/database-design.md](docs/database-design.md)**。

ER 图见 **[docs/er-diagram.md](docs/er-diagram.md)** 与 **[docs/er-diagram.svg](docs/er-diagram.svg)**。

## 核心业务约束的实现方式

本设计的主要思路是：**把业务约束尽量下沉到数据结构层，而不是依赖应用层判断**。这样约束无法通过前端或接口绕过。

| 任务书约束 | 实现方式 | 强制层级 |
|---|---|---|
| 同一课程同设备仅签到 1 次，**无例外** | `records` 复合唯一索引 `courseId + deviceId` | **数据库索引**（并发安全） |
| 超出阈值禁止签到 | 云端 Haversine 计算并裁决（客户端只上报坐标） | 云函数 |
| 不支持一门课程多个签到点位 | 无点位数组字段、无点位关联表 | **数据库结构** |
| 不设置签到起止时间 | `courses` 表无 `startTime`/`endTime` 字段 | **数据库结构** |
| 不区分迟到 / 缺勤 | `records` 表无 `status` 字段 | **数据库结构** |
| 学生不需要密码 | `users` 表无 `password` 字段 | **数据库结构** |
| 学生不绑定微信 openid | `users` 与 `records` 表**均无 openid 字段** | **数据库结构** |
| 无操作日志 | 无独立 log 集合，仅保留记录行内的溯源字段 | **数据库结构** |
| 无消息推送 | 无订阅消息相关字段与调用 | 结构上不存在 |

### 为什么去重必须靠数据库唯一索引

签到云函数的逻辑是"先查是否已签到，再插入"。当同一设备的两次请求**并发**到达时：

```
请求 A: 查询 -> 未签到 ┐
请求 B: 查询 -> 未签到 ┘  两次查询都返回"未签到"
请求 A: 插入 -> 成功
请求 B: 插入 -> 若无唯一索引，也成功   ❌ 同一设备签到 2 次，规则被破坏
```

加上复合唯一索引后，请求 B 的插入会被数据库**原子性**地拒绝，云函数捕获重复键错误后返回"已签到"。

因此该索引是**业务功能的组成部分，不是可选的性能优化**。

## 已知局限与设计取舍

### 1. 设备 ID 可以被清除（重要）

微信小程序**没有官方设备唯一标识 API**，因此设备 ID 由小程序端生成 UUID 并保存在本地缓存中（`utils/device.js`）。

**已知可绕过场景**：

- 删除小程序后重新进入 → 本地缓存被清除 → 生成新 ID
- 在微信中清除小程序缓存
- 使用多个微信号（学生端本身不绑定 openid）

**为什么不用硬件指纹做主键**：`brand + model + platform` 等字段**不是唯一标识**，同型号手机完全相同。若用它判定，班级里只要有两台同型号手机，第二个人起就会被误判为"已签到"而无法签到，且管理员无法区分"他真签过了"和"他和别人手机型号相同"。这种**系统性误判**比"可被主动绕过"更严重。

**缓解措施**：签到记录中同时保存 `deviceFingerprint`（硬件指纹哈希），管理员可在记录中直观发现"同一指纹 + 不同设备 ID"的异常组合，人工识别规避行为。数据库唯一索引保证并发场景下不会写入重复记录。

详细权衡见 [`docs/design-decisions.md` D1](docs/design-decisions.md#d1--设备-id-的获取方案--最高风险项)。

### 2. 距离使用球面模型

使用 Haversine 公式，地球半径取 IUGG 推荐平均值 6371008.8 米。与 WGS84 椭球模型相比存在约 0.1% 的差异（赤道 1 度经度：球面 111195 米 vs 椭球 111319 米）。

在几十到几百米的签到判定场景下，该差异（13 米距离处约 0.04 米）远小于手机 GPS 自身的定位误差，因此球面模型完全够用。

### 3. 学生与课程之间没有绑定关系

学生名单由 Excel 导入且不含课程信息，签到采用**开放式模型**：学生登录后选择要签到的课程。

原因是任务书**未要求任何选课／排课功能**，也未要求"只有选了课的学生才能签到"。若需要该限制，可在 `courses` 增加 `allowClassNames` 数组字段并在 `signIn` 中追加判定，**无需改动现有表结构**。本项目默认不启用，以严格贴合需求边界。

### 4. 定位精度的客观限制

室内定位误差常见 30～100 米。默认阈值 50 米在室内可能导致学生即使在场也无法签到。建议：

- 室内签到把阈值设为 100～200 米；
- 或要求学生在靠窗／室外位置签到。

系统在超出范围时会**显示实际距离**，便于学生判断是"真的不在范围内"还是"定位漂移"。

### 5. 删除课程不会级联删除签到记录

`courses` 与 `records` 之间是逻辑外键（云开发不支持外键约束）。删除课程后，其签到记录仍然保留，列表与导出中显示为"课程已删除"。

这是有意为之：签到记录属于教学凭证，不应因课程配置变更而丢失。

## 常见问题

**Q: 学生登录提示"学号与姓名不匹配"？**
检查 `users` 集合中是否存在该学号，且姓名完全一致（不做模糊匹配、区分空格）。可以在开发者工具 → 云开发控制台 → 数据库中直接查看。

**Q: 管理员登录提示"当前微信账号不是管理员"？**
把弹出的 openid 填入 `login` 云函数的环境变量 `ADMIN_OPENIDS`（多个用英文逗号分隔），保存后重新部署或等待配置生效，然后重新登录。

**Q: Excel 导入提示"未找到表头"？**
Excel 第一行（或前 10 行内）必须包含「班级」「姓名」「学号」三列表头。列的**顺序不限**，也允许有其他列。表头可以是英文（`class` / `name` / `studentId` 等）。

**Q: 导入部分失败？**
属于正常情况。云函数会返回逐行失败原因（学号为空的、学号重复的、学号已存在的等），小程序会弹窗展示前 10 条明细。**失败的行不影响其他行导入。**

**Q: 导出 Excel 时提示"云函数未部署：export"？**
`export` 云函数未上传，或上传时没有选择「云端安装依赖」（它依赖 `xlsx`）。

**Q: 签到提示"定位数据不合法"？**
`wx.getLocation` 返回的经纬度未通过云端校验（越界或为 `(0,0)`）。常见原因是模拟器定位异常，请用真机预览测试。

**Q: 修改公共模块后，各云函数没生效？**
公共模块通过复制分发到各云函数。修改 `cloudfunctions/_common/` 后需要执行：

```bash
node scripts/sync-common.js
```

然后**重新上传**受影响的云函数。

**Q: 学生端不显示任何课程？**
学生端只展示 `status === 1` 的启用课程。请在课程管理中确认课程已启用。

## 开发约定

- 云函数统一返回 `{ code, msg, data }`，`code === 0` 表示成功，错误码表见 `cloudfunctions/_common/response.js`
- 小程序端不直接操作数据库，一律通过 `utils/api.js` 调用云函数
- 所有业务异常通过 `BizError` 抛出，由 `withHandler` 统一转换为返回体，避免云函数以 error 形式返回导致前端难以解析
- 中文注释，关键决策处标注对应的文档章节
