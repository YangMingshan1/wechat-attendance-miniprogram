# 部署指南（从零到跑通）

面向第一次部署本项目的人。按顺序做完这 8 步，就能在小程序里完整走通管理员与学生两条流程。

> 本文比 [README](../README.md#快速开始部署步骤) 更详细，把每一步的**判断标准**和**常见报错**都写出来了。正常情况约 30–45 分钟。

---

## 0. 先确认三件前置条件

| 条件 | 怎么确认 | 不满足会怎样 |
|---|---|---|
| 已注册**小程序**账号（不是公众号、不是订阅号） | 登录 <https://mp.weixin.qq.com> 能看到小程序后台 | 无法开通云开发 |
| 拿到 **AppID**（`wx` 开头的 18 位） | 后台 → 开发管理 → 开发设置 → AppID | 用测试号**不能**用云开发 |
| 装了**微信开发者工具**（稳定版） | 官网下载安装 | — |

> ⚠️ 个人主体的小程序**可以**用云开发，但 `wx.getLocation` 需要在后台申请开通（见第 7 步）。个人主体通常也能通过，但请预留审核时间。

---

## 1. 导入项目

1. 打开微信开发者工具 → **导入项目**
2. **目录**：选择本项目根目录（就是含 `project.config.json` 的那一层）
3. **AppID**：填你自己的 AppID
4. 后端服务：选**不使用云服务**也行（下一步在工具内开通）
5. 点击导入

**判断标准**：工具打开后左侧文件树能看到 `miniprogram/`、`cloudfunctions/`、`docs/` 等目录。

> 如果你在 `project.config.json` 里看到 `"appid": "touristappid"`，说明用的是占位值。用工具导入时填的 AppID 会写进本地配置，一般不用手改；若工具报"AppID 不合法"，就手动把 `project.config.json` 里的 `appid` 改成你的。

---

## 2. 开通云开发环境

1. 工具栏点击 **云开发** 按钮
2. 按引导开通（选**免费基础版**足够，本项目数据量很小）
3. 创建环境，环境名随意（如 `signin-prod`）
4. 创建完成后记下 **环境 ID**（形如 `signin-prod-1a2b3c4d5e6f7g8h`）

**要不要改代码？**

本项目 `miniprogram/app.js` 里用的是：

```js
wx.cloud.init({
  env: wx.cloud.DYNAMIC_CURRENT_ENV,
  traceUser: true
})
```

`DYNAMIC_CURRENT_ENV` 会自动使用当前小程序的**默认云环境**。

- **只有一个环境** → 不用改任何代码，直接进下一步
- **有多个环境** → 把 `wx.cloud.DYNAMIC_CURRENT_ENV` 换成具体的环境 ID 字符串：

  ```js
  env: 'signin-prod-1a2b3c4d5e6f7g8h',
  ```

**判断标准**：云开发控制台能打开，左侧能看到「数据库」「存储」「云函数」菜单。

---

## 3. 部署 7 个云函数

在工具左侧展开 `cloudfunctions` 目录，会看到 7 个云函数目录：

```
init  login  course  student  record  signIn  export
```

**对每一个目录**：右键 → **上传并部署：云端安装依赖（不上传 node_modules）**

逐个操作，7 个都要做。

**为什么要选"云端安装依赖"**：`student` 和 `export` 依赖 `xlsx`（SheetJS）做 Excel 解析与生成。本地没有 `node_modules`（项目刻意不提交依赖），必须让云端安装。

> 如果你只看到「上传并部署：所有文件」，先确认工具版本；旧版本可能在右键菜单的「上传并部署」子项里。

**判断标准**：打开 云开发控制台 → 云函数，列表里能看到 7 个函数，且每个的「状态」正常、有「最后更新时间」。

### 常见报错

| 报错 | 原因 | 解决 |
|---|---|---|
| `Cannot find module 'xlsx'` | 上传时没选"云端安装依赖" | 重新右键该函数 → 云端安装依赖 |
| `cloudfunctions 目录不存在` / 右键没有菜单 | `project.config.json` 里的 `cloudfunctionRoot` 没生效 | 确认该字段是 `"cloudfunctions/"`，重启工具 |
| 上传超时 | 网络问题 | 重试，或用工具内的"上传并部署"重试 |

---

## 4. 认领管理员

**这一步不用抄 openid，也不用配环境变量。** 直接在小程序里点两下完成。

### 4.1 操作

1. 开发者工具点「**编译**」运行小程序
2. 首页 →「**管理员登录**」
3. 点页面底部的「**部署者入口：认领管理员 / 查看 openid**」
4. 弹窗会显示你的 openid → 点「**确定**」
5. 提示「认领成功」→ 自动进入管理后台

**验证**：云开发控制台 → 数据库 → `admins` 集合 → 应有一条记录，`openid` 是你的。

### 4.2 认领入口的安全限制

认领入口有三道闸门，**必须同时满足**才放行：

| 闸门 | 作用 |
|---|---|
| 必须携带微信身份 | 必须从**真实小程序客户端**发起，开发者工具的「云端测试」拿不到身份，会失败 |
| `admins` 集合必须为空 | 已有管理员就不能再认领 |
| 未配置 `ADMIN_OPENIDS` | 配了环境变量就走白名单，认领关闭 |

所以它**只在"全新部署、还没有任何管理员"的窗口期可用**，一旦认领成功入口立即失效，别人抢不了。

### 4.3 后续新增管理员

控制台 → 数据库 → `admins` 集合 → 添加记录（JSON 模式）：

```json
{"openid":"对方的openid","nickName":"管理员"}
```

> **不要用 `ADMIN_OPENIDS` 环境变量管理管理员。** 那条路径虽然代码仍兼容，但它在部署阶段极易出错（值填错、云端测试无身份、忘记重新部署都会导致登录失败），而且报错信息不直观。`admins` 集合里的记录看得见、改得动、能删，是更可靠的做法。

## 5. 建集合与索引

### 5.1 建 5 个集合

云开发控制台 → 数据库 →「＋」→ 依次新建：

```
courses   users   records   admins   devices
```

### 5.2 ⚠️ 建索引（最关键的一步）

控制台 → 数据库 → 选中集合 → **索引管理** → 新建索引。

**必须先建这一条：**

| 集合 | 索引名 | 字段 1 | 字段 2 | 唯一 |
|---|---|---|---|---|
| `records` | `uk_course_device` | `courseId` 升序 | `deviceId` 升序 | ✅ **勾选** |

**为什么它不能省**：这是"同一课程同设备仅签到 1 次"这条业务约束的**唯一实现载体**。

签到云函数是"先查有没有签过，再插入"。当同一设备的两次请求**并发**到达时，两次查询可能都返回"未签到"，于是两条记录都被写入，规则被破坏。只有数据库的**唯一索引**能原子性地拒绝第二条——这才是"无例外"的真正兑现点。

**少了它，功能看起来完全正常，但并发下会产生重复签到记录。** 实测确认：微信云开发的服务端 SDK **不提供** `createIndex` 方法（调用会报 `db.collection(...).createIndex is not a function`），因此**只能手工建立**。

**其余 6 个索引：**

| 集合 | 索引名 | 字段 | 唯一 |
|---|---|---|---|
| `records` | `idx_course_time` | `courseId` 升序 + `signTime` **降序** | 否 |
| `records` | `idx_sno` | `sno` 升序 | 否 |
| `users` | `uk_sno` | `sno` 升序 | ✅ **勾选** |
| `courses` | `idx_status` | `status` 升序 | 否 |
| `admins` | `uk_openid` | `openid` 升序 | ✅ **勾选** |
| `devices` | `uk_device` | `deviceId` 升序 | ✅ **勾选** |

共 **4 个唯一索引**，别漏勾。字段与用途的完整说明见 [database-design.md](database-design.md#7-索引清单--部署必做)。

### 5.3 关于 `init` 云函数

项目里的 `init` 云函数可以自动建集合，但**索引建不了**（SDK 限制）。所以它只能省下"点 5 下新建集合"这点工夫，却引入了鉴权配置的复杂度。

**推荐直接按 5.1 / 5.2 手工建，跳过 `init`。** 如果你仍想用它：

```json
{ "action": "setup" }
```

它会返回 `needManualIndexes`，列出哪些索引需要手工补建——最终仍然要在控制台建。

> `init` 的鉴权策略：配了 `ADMIN_OPENIDS` 就必须是管理员；配了 `INIT_TOKEN` 可用 `{"action":"setup","setupToken":"令牌"}`；两者都没配则放行首次初始化。**注意：云端测试不携带微信身份，所以一旦你配了 `ADMIN_OPENIDS`，`init` 就会因拿不到身份而失败**——这也是建议跳过它的原因之一。

**为什么非要这个索引**：它是"同一课程同一设备只能签到 1 次"这条业务约束的**唯一实现载体**。云函数的"先查再插"在并发下会失效——两个请求可能同时查到"未签到"，然后各写一条记录。唯一索引由数据库原子性地拒绝第二条，这才是"无例外"。

**少了它，功能看起来完全正常，但并发下会写进两条记录。** 这一点在验收和答辩时都会被问。

### 其余 6 个索引清单

| 集合 | 索引名 | 字段 | 唯一 |
|---|---|---|---|
| `records` | `idx_course_time` | `courseId` 升序 + `signTime` 降序 | 否 |
| `records` | `idx_sno` | `sno` 升序 | 否 |
| `users` | `uk_sno` | `sno` 升序 | **是** |
| `courses` | `idx_status` | `status` 升序 | 否 |
| `admins` | `uk_openid` | `openid` 升序 | **是** |
| `devices` | `uk_device` | `deviceId` 升序 | **是** |

**判断标准**：数据库里能看到 5 个集合；`records`、`users`、`admins`、`devices` 的唯一索引都在。

## 6. 设置集合权限（安全必做）

云开发控制台 → 数据库 → **对 5 个集合逐一**设置：

选中集合 → 右上「权限设置」→ 选择「**所有用户不可读写**」

对应的自定义安全规则 JSON：

```json
{ "read": false, "write": false }
```

5 个集合都要做：`courses`、`users`、`records`、`admins`、`devices`。

**为什么**：云开发默认权限是"仅创建者可读写"。而本系统需要管理员**跨用户**读取全部签到记录，学生又**不绑定 openid**，默认权限模型无法表达。所以干脆全部关掉客户端直连，所有数据操作都走云函数（云函数用管理端权限，不受此限制）。

**判断标准**：在小程序里执行下面这行，应该报**权限错误**；如果返回了数据，说明权限没设对：

```js
wx.cloud.database().collection('records').get().then(console.log).catch(console.error)
```

> 本项目前端代码里**没有任何** `wx.cloud.database()` 业务调用，所以关掉权限不会影响功能。

## 7. 申请定位接口权限 + 声明隐私协议

这一步不做，`wx.getLocation` 在真机上会**直接失败**，签到功能整个走不通。

### 7.1 申请接口权限

小程序管理后台（<https://mp.weixin.qq.com>）→ 开发 → 开发管理 → **接口设置** → 找到并申请开通：

- **`wx.getLocation`**（获取当前地理位置）
- **`wx.chooseLocation`**（打开地图选择位置）

本项目已在小程序 `app.json` 里声明了 `requiredPrivateInfos`，但**声明不等于开通**，必须在后台申请并通过。

### 7.2 声明用户隐私保护指引

小程序管理后台 → 设置 → 服务内容声明 → **用户隐私保护指引** → 填写并提交：

| 收集的信息 | 用途填写 |
|---|---|
| 位置信息 | 用于判断学生是否在签到点位的允许范围内 |

**自 2023 年起，未声明隐私协议的小程序调用 `wx.getLocation` 会被拦截。** 这是最常见的"代码没问题但真机定位失败"的原因。

### 7.3 用真机测试

开发者工具里的定位是**模拟的**，只能验证流程，不能验证真实距离判定。

工具 → 预览 → 手机扫码 → 在真机上测试签到。

**判断标准**：真机上进入签到页能弹出定位授权，授权后能拿到定位并完成签到判定。

## 8. 跑通完整流程

### 8.1 管理员侧

1. 首页 →「管理员登录」→ 微信授权 → 进入工作台
2. 「课程管理」→「＋ 新增课程」
3. **点击上方地图区域**选点（会打开微信地图），选好后经纬度自动填充
4. 填写课程名称；阈值保持默认 **50**（或改成 100～200，室内建议放宽）
5. 保存
6. 「学生名单」→ 右上「⇪」→ 选择 Excel 文件导入

   准备一个 Excel，第一行是表头（**列的先后顺序不限**，也可以有额外的"序号""备注"列）：

   | 班级 | 姓名 | 学号 |
   |---|---|---|
   | 软件工程 2301 班 | 李小明 | 20230101001 |
   | 软件工程 2301 班 | 王小红 | 20230101002 |

   导入后会弹窗显示"成功 N 条，失败 M 条"以及失败原因。

### 8.2 学生侧

1. 首页 →「学生登录」→ 输入刚导入的学号与姓名 → 登录
2. 选择课程 →「立即签到」
3. 在允许范围内 → 签到成功；超出范围 → 提示实际距离
4. 再签一次同一课程 → 提示"您已完成签到"

### 8.3 验证核心约束

| 要验证的约束 | 怎么验 |
|---|---|
| 超出阈值禁止签到 | 把阈值临时改成 1 米，此时几乎必然超范围，观察拦截提示 |
| 同课程同设备仅 1 次 | 签到成功后再次进入同一课程 |
| 并发下仍然只有 1 条 | 见下方"并发测试" |
| 不绑定 openid | 控制台看 `records` 与 `users`，**不应有** `openid` 字段 |

**并发测试（证明唯一索引真的生效）**

在开发者工具 Console 里同时发两次相同参数的签到请求：

```js
const payload = {
  courseId: '填一个课程ID',
  sno: '20230101001',
  name: '李小明',
  deviceId: 'test-device-001',
  latitude: 30.512345,
  longitude: 114.365432
}
Promise.all([
  wx.cloud.callFunction({ name: 'signIn', data: payload }),
  wx.cloud.callFunction({ name: 'signIn', data: payload })
]).then(r => console.log(r.map(x => x.result)))
```

**预期**：一次返回 `code: 0`（成功），一次返回 `code: 411`（已签到）。然后去 `records` 集合查 `courseId + deviceId`，**只应该有 1 条记录**。

如果出现了 2 条，说明 `uk_course_device` 唯一索引没建上，回第 5 步。

## 常见问题速查

| 现象 | 原因 | 解决 |
|---|---|---|
| 提示"云函数未部署：xxx" | 该云函数没上传 | 右键上传并部署 |
| `Cannot find module 'xlsx'` | 没选"云端安装依赖" | 重新部署 `student` / `export` |
| 提示"当前微信账号不是管理员" | openid 没加入白名单 | 回第 4 步 |
| 学生登录提示"管理员尚未导入学生名单" | `users` 集合为空 | 先导入 Excel |
| 导入提示"未找到表头" | Excel 前 10 行内没有「班级」「姓名」「学号」表头 | 检查表头文字 |
| 真机定位失败 / 不弹授权框 | 接口权限未开通或隐私协议未声明 | 回第 7 步 |
| 签到提示"定位数据不合法" | 模拟器定位返回了异常值（如 0,0） | 用真机测试 |
| 导出 Excel 没反应 | `export` 未部署或缺 `xlsx` | 重新部署该函数 |
| 提示"暂无可签到的课程" | 课程被停用 | 课程管理里启用 |
| 修改了 `_common/` 但线上没变 | 公共模块是复制分发的 | 执行 `node scripts/sync-common.js` 后**重新上传**受影响的云函数 |

## 部署后的自查清单

- [ ] 5 个集合都存在
- [ ] `records` 的 `uk_course_device` **唯一**索引已建立 ← 最重要
- [ ] `users.sno`、`admins.openid`、`devices.deviceId` 唯一索引已建立
- [ ] 5 个集合权限都是「所有用户不可读写」
- [ ] 7 个云函数都已部署，`student` / `export` 已装 `xlsx`
- [ ] `admins` 集合中有你的管理员记录（openid 正确）
- [ ] 后台已开通 `wx.getLocation` 与 `wx.chooseLocation`
- [ ] 已声明用户隐私保护指引（位置信息）
- [ ] 真机能完成一次签到
- [ ] 并发测试只产生 1 条记录
